# 读到一半被压缩，口令还要写出来

工作区有 part1.txt 到 part6.txt，每份大约 3200 个汉字。按本机 `TokenEstimator`，汉字 1 字约 1 token。工具定义和系统提示大约 9270 token，阈值仍是 20000，不改。

读完 3 份大约 9270 + 9600 = 18870，还在阈值下。读完 4 份大约 22070，应该在第 3 到第 4 份之间触发压缩。如果一次真跑没有落在这个区间，改文件长度，不改阈值。

part2.txt 和 part5.txt 的中段各有一条口令。给模型的原话：

> 工作区里有 part1.txt 到 part6.txt。请按编号从小到大读完。part2.txt 和 part5.txt 里各有一行以 CODE- 开头的口令。把这两条口令原样写进 ANSWER.txt，每行一条。不要修改任何 part 文件，也不要读取 part 以外的文件。

通过要同时满足：ANSWER.txt 里两条口令都在，六个 part 文件的哈希都没变，readFile 的路径都是 partN.txt，并且压缩发生在第 0 轮之后。压缩没发生，或发生在进循环之前，算无效，不进分母。

任务完成（口令写对）和约束守住（文件没被改、没读别的文件）分开记。压缩前读过、压缩后又读的文件个数记在 recoveryReads。
