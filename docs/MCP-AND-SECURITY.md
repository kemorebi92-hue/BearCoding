# MCP、权限与安全边界

BearCoding 是 MCP 的 Host，不是 MCP Server。外部进程或 HTTP 服务提供工具，本进程负责连接、把工具放进 Agent 循环，并在执行前做权限判断。

实现主要在 `backend/src/main/java/com/example/jingjingai2/mcp/` 和 `permission/`。

## 连接

`app.mcp.enabled` 在源码里默认 `true`。没有配置服务器、数据库里也没有已启用的服务时，不拉子进程，工具目录为空。主循环仍使用内置工具。

打开之后有两种传输：

- **stdio。** `StdioMcpSession` 按配置的命令拉起本地进程，通过标准输入输出说话。
- **Streamable HTTP。** `HttpMcpSession` 连接配置的 URL。Bearer 令牌不写进会回显的配置；在服务卡片里单独保存。

管理接口在 `McpServerAdminController`。页面路由是 `/mcp`。保存新服务时默认不自动授权。改已有服务的配置时，在同一个 Slot 上更新并重连，避免本轮已经交给模型的回调因为 Slot 被拆掉而全部失败。删除后再用同名新建，仍然会使旧回调失效。

工具多的时候，`app.mcp.tool-loading` 默认 `auto`：暴露的工具个数超过 `auto-eager-max-tools`（8），或工具定义估算达到参考窗口的一定比例，就改为先 `mcpToolSearch` 再激活。否则一次下发。这个参考窗口只用于 MCP 加载判断，聊天压缩用的是所选模型自己的窗口。

子代理房间默认没有 MCP 工具。

## 权限

会话模式有三档，存在会话记录里。旧数据缺字段时按 `ASK`。

| 模式 | 行为 |
|---|---|
| `ASK` | 默认。敏感工具每次询问。拒绝就不执行 |
| `WORKSPACE_EDIT` | 你在该会话里选择的。工作区内一批普通写文件可以不再次询问。`deletePath` 和 `executeCommand` 不在这批里面 |
| `FULL_ACCESS` | 你在该会话里选择的高权限，不是系统默认。指定的本地文件和命令可以不再次询问。MCP、MCP 管理工具、用户记忆的保存和删除不在这批里面 |

内置规则在 `PermissionPolicy`。读文件、列目录、搜索、建计划、子代理、`webSearch`、`searchContext`、`mcpToolSearch` 和工作区记忆的 `saveMemory` 默认为 `ALLOW`。写入、移动、复制和 `executeCommand` 默认为 `ASK`，并可以「本会话允许」。`deletePath` 是 `ASK`，但不能本会话放行。

`saveUserMemory` 和 `forgetUserMemory` 也是 `ASK`，而且不能「本会话允许」。卡片上能看到类别、键和内容。不批准不会写入或删除。`WORKSPACE_EDIT` 和 `FULL_ACCESS` 的免审批名单里没有这两项，选了更高权限也要单独确认。

写入前还有一层格式拒绝：明显的私钥、`api_key=` / `sk-` 一类访问令牌，以及「密码是 …」这样的口令，即使批准也不会入库。这不能识别所有秘密格式。提示词要求只保存用户在当前轮次里明确说过的内容；代码不另做来源判断，未批准就是未写入。

未登记的工具也是 `ASK`。

命令是否高危由 `CommandSafetyChecker` 判断。高危命令即使工具本身允许「本会话允许」，这一次也不能跳过确认。

MCP 工具另有用户策略：`ALLOW`、`ASK`、`DENY`。没配时默认 `ASK`。`DENY` 不是靠一张写在配置里的白名单，内网和非 http(s) 的限制在代码里。暴露一个工具不等于允许执行。

审批有超时（默认 120 秒）。超时或停止后，等待中的审批应进入终态，而不是一直占着会话。等待期间策略变严，会再查一次，不沿用已经过期的允许。

读过不可信内容之后，默认策略是 `ask`：危险的内置工具改为逐次审批。`off` 可以关掉这层，那是配置选择，不是默认。

**这层覆盖面的边界**：目前只有 MCP 服务的工具结果会按服务声明的 untrusted 标记置污点（`McpUntrustedGuard` / `McpClientManager.noteToolResult`）。`webSearch` 抓回来的网页正文**不会**置污点，所以「读过网页 → 免审批的 `saveMemory` 仍可直接写」是当前已知缺口，不要把它当成已经防住的路径。

## 凭证

MCP 令牌和环境变量里的秘密不放进 git，也不从管理接口的普通回显里返回。

密文格式在 `McpCredentialCrypto`：版本前缀加上 Base64（随机 nonce 和 AES-GCM 密文）。密钥材料来自数据根 `secrets` 下的 DPAPI 文件，不来自源码。模型 API Key 和工具引用签名用另外两份密钥文件，互不混用。

数据库还在、密钥文件缺失或损坏时，启动失败。不会生成一把新密钥再把旧密文当成可读。

## 大结果

单条 MCP 结果超过该服务的 `max-result-chars` 时，默认把全文写到落盘目录，模型只看到预览和引用。`spill-enabled=false` 时退回头尾截断，不写盘。

落盘有存活时间和单会话体积上限。引用带 HMAC。校验失败就失败，不把损坏的文件当成原文。

只读路径检查对「当前会话的 MCP 落盘目录」有例外，而且用真实路径比较，拒绝 UNC。写和命令工具没有这个例外。

## 工作区与命令

`PathSandbox` 把读写限制在当前工作区根里：规范化绝对路径之后做前缀判断，挡住 `..` 和越界绝对路径。

这是路径级检查，不是进程级沙箱，也不是容器或操作系统隔离。`FULL_ACCESS` 会放宽「必须落在工作区内」这一条，命令注入、危险命令、用户记忆和 MCP 权限仍按各自规则。高危命令在这一档下不再逐次确认，因为命令工具在它的免审批名单里。这是使用者主动打开的行为，不是默认。

命令参数里像路径的部分，默认也必须落在工作区内。`FULL_ACCESS` 只放开这一条范围限制，其余检查还在。

绑定的是用户给出的本机目录时，Agent 改的就是那个目录里的文件。默认工作区则是上传后的副本，不是用户原来的路径。

## 没有被验证成什么

单元测试覆盖了路径越界、危险命令、审批超时、用户记忆的批准与拒绝、MCP 重连、凭证往返和 URL 拒绝等分支。真实模型上的一次完整任务和本机 MCP 已经验收过，但这不能写成：

- 已经用真实外部 MCP 服务完成验收（只用过本机自建的 MCP）
- 操作系统级隔离
- 能识别每一种密钥格式
- 多用户部署下可以共享有状态的 MCP 进程

真实外部 MCP 和 Playwright 现场测试没有作为本版的通过项。`ACCEPTANCE.md` 是清单，不是已经逐项通过的报告。
